Deployment Runbook

Last updated 12 days ago · Platform Team

This runbook covers the standard release path for platform services. Follow the staged rollout order and confirm each gate before promoting to the next environment.

Release gates

Every release must pass integration tests in staging before promotion. The canary stage holds for 30 minutes with automated rollback on error-rate regression. Promotion beyond canary requires a green dashboard and an acknowledged on-call handover.

Rollback

Rollback is a redeploy of the previous tag, not a revert commit. Database migrations are forward-only; if a migration is implicated, page the on-call DBA rather than attempting a schema rollback from the deploy pipeline.

Escalation

If a release stalls at canary for more than one hold period, escalate to the platform lead. Do not promote a stalled canary manually.
